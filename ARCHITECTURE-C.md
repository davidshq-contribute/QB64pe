# ARCHITECTURE-C.md

Architecture of the C/C++ runtime library and dependencies.

## Runtime Library: internal/c/libqb/

The libqb library provides the QB64 runtime - all built-in functions that execute at runtime.

### Directory Structure

```

├── src/           # Implementation files (~41 files)
├── include/       # Header files (~30 files)
└── build.mk       # Build configuration
```

### Key Data Structures

#### qbs (QB String Descriptor)

```cpp
struct qbs {
    uint8_t *chr;              // Pointer to string data
    int32_t len;               // String length
    uint8_t in_cmem;           // In conventional memory
    uint16_t *cmem_descriptor; // CMEM descriptor pointer
    uint32_t listi;            // String list index
    uint8_t tmp;               // Temporary string flag
    uint32_t tmplisti;         // Temp list index
    uint8_t fixed;             // Fixed-length string
    uint8_t readonly;          // Read-only flag
    qbs_field *field;          // FILE field association
};
```

String descriptors are allocated from pools (65536-entry pools) for efficiency.

#### img_struct (Image/Screen)

```cpp
struct img_struct {
    uint16_t width, height;
    uint8_t bytes_per_pixel;
    uint8_t bits_per_pixel;
    uint32_t compatible_mode;  // 0,1,2,7,8,9,10,11,12,13,32,256
    uint32_t color, background_color, draw_color;
    // ... clipping, view, scaling, print position
    // ... font, alpha, blend settings
};
```

#### mem_block and mem_lock

Low-level memory access with security locking for `_MEM` functions.

## Entry Points

### qbx.cpp (~1,743 lines)

The wrapper that includes generated QB64 code:
- Includes all libqb headers
- Platform detection and initialization
- Window creation and event loop setup
- `#include`s the generated code from `internal/temp/*.txt` in a fixed order: `global.txt`, `regsf.txt`, `dyninfo.txt`, `clear.txt`, `inpchain.txt`, `chain.txt`, `onstrig.txt`, `onkey.txt`, `ontimer.txt`, `maindata.txt`, `mainerr.txt`, `runline.txt`, `ontimerj.txt`, `onkeyj.txt`, `onstrigj.txt`, then `main.txt`. The file `main.txt` is generated by the compiler as an aggregator that contains `#include "main0.txt"`, `#include "main1.txt"`, etc. (main0 = main program, main1..mainN = SUB/FUNCTION bodies).
- vWatch debugging hooks

### libqb.cpp (~31,000 lines)

Pre-compiled runtime functions:
- Includes all libqb source files via headers
- Compiled with feature-specific preprocessor flags
- Object file named with bit pattern encoding features

## Build System

### Makefile Structure

**Platform Detection:**
```makefile
OS = lnx | win | osx    # Required
```

**Compiler Configuration:**
- Linux: System GCC, `-no-pie`
- Windows: Bundled MinGW or system compiler
- macOS: Xcode Clang with frameworks

**Global Compiler Flags:**
```
-std=gnu++20            # C++20 standard
-fno-strict-aliasing    # Required for QB64 type system
-Wall -Wextra           # Warnings (disabled for third-party code)
```

### Dependency Flags

Each `DEP_*` flag controls:
1. Preprocessor define (`-DDEPENDENCY_*`)
2. Source file inclusion
3. Library linking

| Flag | Preprocessor | Effect |
|------|--------------|--------|
| `DEP_GL` | `DEPENDENCY_GL` | OpenGL/graphics support |
| `DEP_SCREENIMAGE` | `DEPENDENCY_SCREENIMAGE` | Screenshot functionality |
| `DEP_IMAGE_CODEC` | `DEPENDENCY_IMAGE_CODEC` | Image loading/saving |
| `DEP_SOCKETS` | `DEPENDENCY_SOCKETS` | Network sockets |
| `DEP_PRINTER` | `DEPENDENCY_PRINTER` | _PRINTIMAGE support |
| `DEP_ICON` | `DEPENDENCY_ICON` | _ICON support |
| `DEP_FONT` | `DEPENDENCY_FONT` | _FONT support |
| `DEP_DEVICEINPUT` | `DEPENDENCY_DEVICEINPUT` | Game controllers |
| `DEP_ZLIB` | `DEPENDENCY_ZLIB` | _DEFLATE/_INFLATE |
| `DEP_CONSOLE_ONLY` | `DEPENDENCY_CONSOLE_ONLY` | No graphics window |
| `DEP_AUDIO_MINIAUDIO` | `DEPENDENCY_AUDIO_MINIAUDIO` | Sound support |
| `DEP_HTTP` | (set with DEP_SOCKETS) | HTTP client |
| `DEP_EMBED` | `DEPENDENCY_EMBED` | $EMBED data |
| `DEP_ICON_RC` | (set when $EXEICON or $VERSIONINFO used) | Windows icon/version resource |
| `DEP_CONSOLE` | (from RCStateVar ConsoleOn) | Console support on Windows |

**Compiler mapping:** The QB64 compiler (`source/qb64pe.bas`) uses `DEPENDENCY_*` constants (e.g. `DEPENDENCY_GL`, `DEPENDENCY_SOCKETS`) and builds `makedeps$` to pass `DEP_*=y` to the Makefile. `DEP_HTTP` is always set when `DEP_SOCKETS` is set. `DEP_ICON_RC` is set when `$EXEICON` or `$VERSIONINFO` is used. `DEP_CONSOLE` comes from the console RCStateVar.

### Object File Naming

The `libqb` object encodes enabled features in its filename:

```
libqb_make_XXXXXXXX.o
         ^^^^^^^^
         8-bit pattern encoding DEP_* flags
```

Example: `libqb_make_00010100.o`

This allows multiple configurations to coexist without rebuilding.

### Linking Order

1. `libqb` objects (from `libqb/build.mk`)
2. Dependency static libraries:
   - `audio.a`, `data_processing.a`, `font.a`, `freetype.a`
   - `image.a`, `freeglut.a`, `clipboard.a`
3. GUI objects (`tinyfiledialogs.o`, `gui.o`)
4. Platform libraries:
   - Windows: `-lcomdlg32 -lole32 -luuid -lshlwapi -lws2_32`
   - Linux: `-lGL -lGLU -lpthread -ldl -lrt -lX11`
   - macOS: OpenGL, GLUT, Cocoa frameworks

## Memory Management

### String Pools

- 65536-entry descriptor pools
- Pool-based allocation for efficiency
- Separate tracking for temporary strings (auto-cleanup)

### Conventional Memory

- Optional C-style memory support
- Compatibility with legacy QB code
- Managed alongside QB64 strings

### _MEM Security

- Memory regions can be locked
- Prevents unauthorized access
- Used for low-level `_MEM` functions
